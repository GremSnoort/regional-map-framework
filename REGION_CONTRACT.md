# Контракт регионального пакета

Регион содержит конфигурацию и преобразования, но не копию frontend-кода.

```text
regions/<region_id>/
├── region.json
├── SOURCES.md
├── sources/
│   └── README.md
├── .runtime/
│   └── publication.json
└── pipeline/
    ├── pipeline.json
    ├── plugins/
    │   ├── README.md
    │   └── <model>.json
    └── requirements-lock.txt
```

Во время локальной работы появляется `data/`, но этот путь и `.runtime/`
исключены из Git.

## `region.json`

Обязательны идентификатор, версия core, жизненный цикл, `data_mode`, заголовки,
параметры карты и объект `layers`. Ключ `layers` — стабильный идентификатор слоя.
Его значение описывает:

- `file` — файл ниже `data/`;
- `label` — подпись в переключателе карты;
- `geometry_types` — разрешённые геометрии;
- `required_properties` — обязательные свойства каждой feature;
- `numeric_properties` — свойства, которые обязаны быть числами;
- `required_for_production` — запрет пустого слоя в production;
- `title_field`, `popup_fields`, `style` — декларативное отображение;
- `default_visible`, `fit_bounds` — начальное поведение карты.
- `renderer` — `points`, `lines`, `polygons`, `choropleth`, `density`, `ranking`;
- `bins`, `value_field`, `size_field` — шкала, цвет и размер;
- `category_field`, `categories` — категориальные цвета и легенда;
- `label_field`, `label_min_field`, `label_min_value` — постоянные подписи по порогу;
- `min_zoom`, `max_zoom` — диапазон отображения;
- `style.fill_max_zoom` — последний масштаб с фоновой заливкой полигона;
  выше него остаётся граница, а прозрачность задаёт
  `style.fill_opacity_above_max` (по умолчанию `0`);
- `z_index`, `interactive` — порядок pane и перехват указателя;
- `table` — сортировка, столбцы, фильтр и связанный детальный слой;
- `unique_by` — проверка уникальности объектов.

Предметные поля не зашиты в core. Слой может представлять магазины, ПВЗ,
медицинские учреждения, земельные участки, здания, зоны спроса или результаты
любой модели.

## Данные

Все файлы должны быть GeoJSON `FeatureCollection` в WGS 84: долгота, затем
широта. Режим `external` поддерживает symlink, Windows junction и локальную
копию. После подключения создаётся publication manifest с SHA-256 каждого слоя.
Изменившийся snapshot требует явной команды `accept-data`.
Manifest также фиксирует хеш контракта `region.json` без поля lifecycle, поэтому
изменение схемы слоя, renderer или контрольных значений требует повторного
принятия/сборки, а безопасное повышение draft → production не ломает provenance.

## Pipeline

`pipeline/pipeline.json` перечисляет точные входы, выходы и команды. Runner:

1. запрещает выход путей за каталог региона;
2. фиксирует SHA-256 входов и зависимости;
3. собирает результаты во временной папке;
4. требует все объявленные выходы;
5. атомарно заменяет outputs и manifest.

`manage.py build` затем транзакционно публикует эти результаты в `data/`.
Набор `pipeline.outputs` обязан в точности совпадать со всеми слоями региона.
Вложенные пути сохраняются. Publication manifest связывает опубликованные
файлы с runner manifest.

## Аналитический plugin

Модель хранится внутри региона и объявляет стабильный `plugin_id`, версию,
входы, выход, методологию, параметры и quality controls. Пример находится в
`templates/analytics-plugin.example.json`. Исполняемый скрипт и его конфигурация
обязаны быть входами шага pipeline и тем самым входить в provenance.

Runner автоматически включает в input lock каждую декларацию из
`pipeline/plugins/*.json`, все перечисленные в ней входы и файл методологии.
Полная сборка `--full` начинается с пустого staging-каталога: устаревший output
не может сохраниться только потому, что очередной шаг забыл его пересчитать.

Общий `build_adaptive_density.py` строит неперекрывающуюся quadtree-сетку. Шаг
между `min_grid_metres` и `grid_metres` выбирается по локальной сложности
жилой застройки (`split_buildings` и `split_proxy_m2_per_km2`), а не только по
размеру всего населённого пункта. Сумма оценок ячеек обязана в точности совпасть
с контрольной численностью. Мелкая ячейка повышает пространственное разрешение,
но не превращает модельную оценку в официальные микрорайонные данные.

## Production

Production-регион обязан иметь все объявленные файлы и согласованный publication
manifest. Каждый слой с
`required_for_production: true` должен содержать хотя бы один объект. Поле
`expected` при наличии фиксирует точные количества features по идентификаторам
слоёв. `doctor` также требует содержательный `source_note`, заполненный
`SOURCES.md`, а для pipeline — хотя бы один воспроизводимый шаг.
