# Региональный каталог партнёров и источников объектов

Модуль ведёт проверяемый справочник публичных профессиональных контактов
агентств недвижимости, брокеров, риэлторов, девелоперов и управляющих
компаний, работающих с выбранным регионом.

Конвейер разделяет получение и публикацию:

```text
источники → сбор → нормализация → дедупликация → проверка → публикация
```

Сбор никогда не заменяет опубликованный каталог. Он записывает новый набор в
`candidates.json`, рассчитывает дельту, после чего администратор проверяет её в
UI и отдельным действием публикует. Публикация выполняется атомарной заменой.

## Границы достоверности

Каталог содержит только публичные деловые и профессиональные контакты. Наличие
записи не является рекомендацией, а отсутствие — подтверждением, что участник
не работает в регионе. Перед обращением пользователь должен сверить сведения с
приведённым первоисточником.

Не добавляйте частные контактные данные, полученные из переписки, закрытых баз
или иных непубличных источников. Для удалённого сбора используйте только
ресурсы, условия которых допускают автоматические запросы. HTML-сбор по
умолчанию проверяет `robots.txt`.

## Региональный контракт

Модуль включается только при наличии:

```text
regions/<region_id>/contacts/sources.json
```

Контракт соответствует `schemas/contacts-sources.schema.json`. Пример находится
в `templates/contacts-sources.example.json`.

Поддерживаются три явных типа источников:

- `local_json` — проверенный вручную seed-файл внутри `contacts/`;
- `remote_json` — публичный структурированный HTTPS-источник;
- `website` — одна организация и явно перечисленные страницы её официального
  сайта.

Для каждого удалённого источника обязателен `allowed_hosts`. Redirect также
проходит эту проверку; адреса локальных, служебных и частных сетей запрещены.
Произвольного обхода домена и автоматического поиска через поисковые системы
модуль не выполняет.

Минимальный интервал между запусками — один час. Для production рекомендуется
`43200` секунд (12 часов) или больше. Между источниками выдерживается
`request_delay_seconds` не менее одной секунды.

## Формат контакта

Seed и JSON-источники принимают массив `contacts`. Пример —
`templates/contacts-seed.example.json`. Основные поля:

- `name` и `kind`;
- `coverage` — регион, города и районы работы;
- `specializations`;
- `phones`, `emails`, `websites`, `addresses`;
- `links` — публичные профили и мессенджеры.

Телефоны, email и URL нормализуются. Дубликаты объединяются по совпадающему
телефону, email, домену сайта либо точному нормализованному названию и зоне
работы. Каждая опубликованная запись сохраняет идентификаторы источников и дату
получения.

## Локальная проверка

После установки `contacts/sources.json` выполните:

```bash
python3 manage.py validate <region_id> --allow-missing-data
python3 manage.py contacts-collect <region_id>
python3 manage.py contacts-status <region_id>
python3 manage.py contacts-publish <region_id>
```

Консольная публикация фиксируется как `console-admin`. В production основной
путь — проверка дельты и публикация из `/contacts.html?region=<region_id>`.

## Production

Добавьте в `/etc/regional-map-framework.env`:

```text
RMF_ADMIN_USERS=map_admin
RMF_ALLOW_CONTACT_COLLECTION=1
```

`RMF_ADMIN_USERS` — разделённый запятыми список уже существующих пользователей.
Только они видят административную панель и могут вызывать mutation API. Простая
авторизация на просмотр карт административных прав не даёт.

Runtime-файлы находятся в:

```text
${RMF_RUNTIME_ROOT}/<region_id>/contacts/
├── candidates.json
├── published.json
├── state.json
└── collection.log
```

Они не входят в Git и не заменяются деплоем кода. Резервно копируйте
`published.json` вместе с credential store. Конфигурация источников и локальные
seed-файлы входят в региональный deployment bundle.

После изменения environment перезапустите сервис. Оставляйте
`RMF_ALLOW_CONTACT_COLLECTION=0`, пока региональные контракты источников не
проверены, а runtime-каталог не доступен на запись service user.
